WHAT THIS PROVES, AND WHY A SECOND REBUILD WAS NEEDED
-----------------------------------------------------
The first rebuild of 2026-08-23 exposed a defect: deploy.sh step 9 resolved the four image digests,
passed them to the release-branch promotion, and left master's values.yaml digests EMPTY. Step 10
Helm-installs from the working tree (master), and step 11 then hands over to ArgoCD, which syncs the
release branch -- so the two appliers rendered DIFFERENT image references for the same field.

It did not error. ArgoCD took ownership cleanly and the end state was correct. The cost was that
every workload rolled TWICE on first deploy:

    FIRST REBUILD (defect):   deployment.kubernetes.io/revision = 2 on all three,
                              with revision-1 pods still terminating
                              git diff master release -> values.yaml AND image-digests.tsv

The fix writes the digests into values.yaml BEFORE committing to master, so both branches carry
identical image references. It could not be tested by the deploy that discovered it -- editing a
running bash script corrupts execution (bash reads lazily by byte offset) -- so it shipped verified
only by reasoning and by scripts/tests/test-promote-to-release.sh. This capture is its first live
exercise.
