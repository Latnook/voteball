# Task 4 evidence -- deliberate broken deploy and automatic rollback (2026-08-17)

A DELIBERATELY BROKEN frontend image was built outside CI (CI would have refused it -- the
failing behaviour is intentional, not a test failure) and pushed under tag dead0be. That tag is
valid hex and passes CD's ^[0-9a-f]{7,40}$ input check, but is deliberately NOT any real commit
in this repository, so no genuine commit ends up with an image that misrepresents its contents.

The break: nginx.conf returns 500 on "/". The frontend's startupProbe targets "/" with a 30s
budget (failureThreshold 10 x periodSeconds 3), and a failing STARTUP probe kills the container
-- so the new pod never became Ready and crash-looped. The other three images were built
unmodified from the same tree.

## Visitor-visible impact: NONE

1,539 probes of https://voteball.latnook.com/ at 2/s spanning 10:11:09 -> 10:26:08 -- the whole
demo, from before the broken deploy to after the recovery -- returned HTTP 200 every time.
See 2026-08-17-task4-rollback-site-poll.txt; check it with:
    awk '$2!=200' docs/eks/evidence/2026-08-17-task4-rollback-site-poll.txt   # no output

That is the rolling-update contract, not luck: a pod that never passes readiness is never added
to the Service's endpoints, and the old ReplicaSet is never scaled down because the rollout
never progresses. Contrast 2026-08-04's demo, where the backend returned 500 while PASSING its
probes -- ArgoCD called that Healthy and only the smoke test caught it, at a cost of ~3 minutes
of real errors. The two demos deliberately exercise different layers.
