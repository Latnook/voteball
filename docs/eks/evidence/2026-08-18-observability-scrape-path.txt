== NETWORK POLICY: the narrowing works, proven by a pair ==
Both ALB ingress rules used to admit 10.0.0.0/16 -- the whole VPC -- to mean "the load
balancer". The AWS VPC CNI gives every POD a VPC address, so that also admitted every pod
in the cluster. Narrowed to the two PUBLIC subnets, where the ALB's interfaces actually are
and where no pod ever runs.

A single probe cannot prove this: a pod that reaches nothing looks identical to a policy
that works. So the evidence is a PAIR, both probes waiting 80s first because the CNI fails
OPEN until the node programs the pod's eBPF maps.

  from namespace external-secrets (no NetworkPolicy at all):
      http://jenkins.ci:8080/  ->  timed out, no response          = blocked
  from namespace ci (the policy admits same-namespace):
      http://jenkins.ci:8080/  ->  HTTP/1.1 403 Forbidden          = reached

The 403 is Jenkins' own auth rejecting an anonymous request -- which is the point: the
service is alive and answering, so the timeout from outside is the policy, not a dead
service.

Verified against reality rather than the template: the live ALB k8s-voteball-327d05a115
sits in subnets 10.0.0.0/20 and 10.0.16.0/20, exactly the CIDRs the narrowed rule admits.

== ALERTMANAGER SURVIVED THE RENAME (the design's named silent failure) ==
The IRSA trust policy names the namespace. Left behind, Alertmanager could not assume its
role -- and alerts would still evaluate, still fire, still show as firing, and never be
delivered.
  trust policy condition : system:serviceaccount:observability
  serviceaccount role-arn: arn:aws:iam::590183895228:role/voteball-alertmanager-irsa
  credential errors in log: 0
  /-/ready: OK
Not yet proven end to end: that an alert actually ARRIVES at the SNS mailbox. That is a
drill in a later plan, not an assertion made here.

== JENKINS IS DELIBERATELY ABSENT FROM THE TARGET LIST ==
ci/jenkins/plugins.txt now carries the `prometheus` plugin, but plugins are baked into the
controller IMAGE and terraform/addon-jenkins.tf sets installPlugins=false. The image tag
comes from jenkins_image_tag in the gitignored voteball.tfvars, still 4993a70 -- so no
image was built and /prometheus does not exist yet.

Its ServiceMonitor is therefore switched OFF (serviceMonitor.enabled=false). Left on, it
would have produced a permanently-failing target, and the stack's own default TargetDown
rule would email SNS every 12 hours indefinitely. It flips to true in the same change that
builds the image and bumps the tag.
