  THE KEY OBSERVATION, and it is the reason drill 5 exists as a separate drill: killing an
  agent ABORTS the build. It does not queue it. So jenkins_queue_size_value never moves and
  JenkinsQueueStuck cannot be proven this way -- which is exactly the gap the morning run
  recorded and left open. To make builds QUEUE you have to break agent PROVISIONING, not kill a
  provisioned agent. That is drill 5's ResourceQuota.

  The website result is the point of this drill: CI is not in the serving path. Jenkins holds no
  cluster write credentials, ArgoCD is the only applier, and the running pods in devops-app do
  not care that a build died. A CI outage is a delivery problem, not an availability problem.
