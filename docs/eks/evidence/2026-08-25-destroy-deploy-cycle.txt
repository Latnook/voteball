REBUILD — the bug the cycle actually found (introduced hours earlier, not predicted):
  GITHUB_TOKEN was added to deploy.env. deploy.sh sources that file with `set -a`, and
  GITHUB_TOKEN is consumed automatically by git's credential helper and the gh CLI. So
  every git push and gh call in the deploy authenticated as a READ-ONLY, single-repo
  fine-grained PAT instead of the operator's own credentials:

    step 9   remote: Permission to Latnook/voteball.git denied to Latnook.
             fatal: ... The requested URL returned error: 403
             ERROR: could not push values.yaml.
             Refusing to bootstrap ArgoCD -- it would sync a stale image tag over this deploy.
    step 11  SKIPPED — values.yaml is not on master (see the error above).
    step 11b gh: Resource not accessible by personal access token (HTTP 403)

  CONSEQUENCE: deploy.sh exited 0, the site served HTTP 200, and the cluster had NO ArgoCD
  Applications at all — charts/observability was never deployed. A successful-looking deploy
  that silently omitted half the platform.

  Fixed: renamed to GRAFANA_GITHUB_TOKEN (ccad3df). Cannot collide.

OPERATOR ERROR WORTH RECORDING
  Step 9 printed "Refusing to bootstrap ArgoCD -- it would sync a stale image tag over this
  deploy." That guard was RIGHT and was overridden by hand. `release` still held the
  DESTROYED cluster's image tag (2ce865c, absent from the rebuilt ECR), so the migrate
  PreSync hook went ImagePullBackOff and blocked the whole sync for ~20 minutes. Recovery
  needed: promote-to-release.sh with correct digests, delete the stuck hook, hard-refresh
  the Application. All of it was predicted verbatim by the message that was ignored.

SECOND DESIGN FAULT FOUND
  Step 11d checked for grafana-datasources ONCE and exited 0 with "nothing to project".
  It runs moments after step 11 bootstraps ArgoCD, ~90s before ESO fills the Secret, so a
  single check is ALWAYS too early on a fresh deploy. Now waits up to 180s (49ad02d).
